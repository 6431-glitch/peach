# ADR-0150：FC2 优先匿名 JavDB，按演员身份补查专站

- 状态：已采纳
- 日期：2026-11-07
- 关系：修订 FC2 的查询顺序；沿用 ADR-0038 的字段归属、ADR-0061 的专站演员优先级和 ADR-0144 的匿名 JavDB 协议。

## 背景

匿名 JavDB 已能按番号取得标题、演员、日期、标签和封面地址，但 FC2 把它放在五个专站之后，可能尚未轮到就耗尽预算。已有不含演员的缓存还会使 FC2 来源循环在演员站之前退出。网页登录墙不代表匿名目录没有作品资料。

JavDB 的演员栏也可能是片中称呼或未确认名义。只看演员列表非空就停，会把这类称呼直接当作规范演员；只靠名字长短同样无法区分化名和正式艺名。

## 决策

1. FC2 元数据按 `javdb → fc2 → fc2cmadb → fc2ppvdb → javten → javarchive` 查询。用户整条覆盖的来源链仍优先。其他内容类型不受影响。
2. 有足够标量字段才停。FC2 的卖家保留为卖家，不冒充厂牌；空厂牌不作为 FC2 单独继续联网的理由。封面继续使用既有图源、解码与质量验证。
3. JavDB 演员须能解析到本机规范实体，且该实体有既有 R18、r18.dev、minnano-av 人名目录依据，或受信的 `identity=person` 断言。已确认别名复用规范实体；单有 JavDB 编号、仅存在一条演员实体或名字形态像人名，都不等于身份已确认。
4. 缺演员、企划名义和未确认名字继续专站。JavDB 的未确认演员留待既有候选机制处理，不自动建规范关联；标题、日期、标签等可用字段照常处理。专站优先级及人工字段保护沿用现有规则。
5. 已有不含演员的缓存只跳过不提供所需字段的来源，不截断后面的演员站。升级后的定向重采须能重读旧完成回执中缺演员的 FC2 行；保留正常证据、现有演员与预览结果。

## 验证

用匿名完整资料、无演员、短名义、敬称及已确认别名分别验证停手与补问；验证未确认演员仍为候选。目录落地使用临时数据库与伪远端验证刷新后同轮入库，协议流式错误保留为可重试故障。
