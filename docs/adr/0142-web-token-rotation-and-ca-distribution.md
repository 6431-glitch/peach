# ADR-0142：配置页更换访问口令与分发本机 CA

- 状态：已采纳
- 日期：2026-11-04
- 相关：ADR-0004、ADR-0137

## 背景

访问口令（`secrets/auth-token`）只能用 `peach token --rotate` 更换，正在运行的服务还要重启才会读到新口令。让手机等设备信任本机 HTTPS 证书，要手动把 `peach-local-ca.crt` 拷到设备上，再用 `openssl` 核对指纹。两件事都要进终端或手动拷文件。

口令和访问密码是两套凭据。设了访问密码的部署，浏览器会话用 `access.json` 里的密钥签名，和口令无关；没有 `access.json` 的老部署，登录页认的就是口令，会话签名密钥也是口令。

手机第一次装证书时，既没有登录，也还不信任这张证书。

## 决策

1. **当场生效**：`POST /api/configuration/access/token/rotate` 原子替换口令文件，并把进程里的运行设置换成新口令，复核镜像发出的口令一并更新，不用重启。命令行 `peach token --rotate` 在别的进程里执行，仍要重启服务。
2. **只换文件里的口令**：服务启动时记下口令来自哪里。口令由 `--token` 或 `PEACH_TOKEN` 覆盖时返回 409；换了文件，下次启动照样用覆盖值，页面上换了也不算数。这次启动没有口令时同样返回 409。
3. **按访问方式登出**：设了访问密码时不动任何浏览器会话和设备记录。老部署的口令就是会话签名密钥，换口令后其他浏览器全部退出，设备记录清空，本机在同一个响应里补签新会话，不会把操作者自己登出。两种情况下，脚本、API 调用和 `?t=` 链接都立即失效。开着双机复制或复核镜像时，页面提示另一台要换成同一份口令文件。
4. **新口令只显示这一次**：沿用凭据不回显的做法，配置读取只返回能不能换、为什么不能换，不返回口令。更换的那个响应带回新口令（`Cache-Control: no-store`），页面显示到离开本页为止。这是界面上的约定，不是一次性密钥：本机终端的 `peach token` 仍能查看口令。
5. **证书只发公开部分**：下载路由不接受文件名参数，只读 `secrets/tls/peach-local-ca.crt`，经 `cryptography` 解析后重新编码为 PEM，文件里拼进了私钥也不会发出去。SHA-256 指纹按 `openssl x509 -fingerprint -sha256` 的格式给出。没有 HTTPS 服务或没有 CA 时，整块不显示。
6. **手机扫码不用先登录**：二维码里的地址带一个进程内密钥签发的签名，10 分钟有效，只能换到这张公开证书；服务重启后旧二维码作废。要求先登录的话，手机就得在还不受信任的连接上输入密码，而装证书正是为了防这种情况。不带签名的下载照常要求登录。指纹和二维码只在本机管理权限下给出。
7. **二维码复用已锁定的 `qrcode==8.2`**：它原是 `p115client` 的传递依赖，现在改为直接依赖。只取模块矩阵，由页面画成 SVG，不经过 Pillow。

## 代价

- 页面开着时每 9 分钟重取一次签名，二维码在扫码时总是有效的。
- 老部署换口令后，其他设备要用新口令重新登录。
- 口令被启动参数覆盖的部署，仍然要在启动配置里换口令。
- Android 浏览器常常解析不了 `.local` 名字。这时在运行 Peach 的电脑上改用局域网 IP 打开配置页，二维码会跟着换成 IP 地址。
