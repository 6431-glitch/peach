# ADR-0152：升级后弹出按平台筛选的版本公告

- 状态：已采纳
- 日期：2026-11-07
- 关系：补充发布流程（ADR-0012）与升级补修；不改变变更日志的写法

## 背景

0.56.0 之后主线合入了二十多个 PR，其中有新入口，也有升级后自动运行的补修（显示尺寸补测、NAS 系统文件隔离）。使用者升级后只能自己翻 Release 页，而变更日志面向全部平台、逐条罗列，不适合直接弹给使用者。Peach 也没有记录「上次运行的是哪一版」，分不出新安装、上一版升级和跳版升级。

## 决策

每个发布版本在 `src/peach/release_notices.py` 写一条公告：新入口、更新后自动进行的事、需要使用者动手的事，每条一句短话。修复与完整清单留给 Release 页。条目可以按系统与安装方式（`platforms`）筛选，也可以按本机数据（`when`，例如确实移出过系统文件、配了 CloudDrive 却没设缓存上限）筛选。不适用的条目不显示。

已读版本记在账本的个人设置里，和教程进度同一份，一个部署只弹一次，换设备不重复。新安装不弹，直接记为已读。上一版升级只显示当前版。跳版升级时，额外折叠列出最多三版错过的要点。补丁版标为 `quiet` 时不弹窗。

0.57.0 之前没有已读记录。老账本第一次升级到带公告的版本时，按迁移记录推断原版本的下界：所有迁移在一小时内应用完的视为新安装，否则取更早一批迁移的最大编号对应的首发版本。推断只给下界，界面写「最近几版」，不写「错过了」。

minor 及以上的版本没有公告时，`scripts/release_tag.py` 的定版准备直接拒绝；补丁版可以不写。

## 后果

- 发版多一项必写内容，但它比变更日志短得多，也防止「未发布」段那样没人写。
- 公告内容随程序包发布，不依赖安装目录里的 `CHANGELOG.md`；「完整更新日志」链接到 GitHub Release 页。
- 公告读取只看本机回执与设置，不发外部请求。

## 验证

`tests/test_release_updates.py` 覆盖新安装、上一版升级、跳版、按迁移推断、按平台与本机数据筛选、已读只前进和公告字段取值；`tests/test_version_bump.py` 覆盖定版门槛。界面经真实小样本预览，在桌面与手机宽度下核对。
