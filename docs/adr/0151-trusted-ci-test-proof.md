# ADR-0151：以受信 CI 测试证明交付相同内容

- 状态：已采纳
- 日期：2026-11-07
- 关系：补充本机正式验证与工作树集成契约，不改变发布制品晋级

## 背景

本机测试记录绑定源码快照和实际环境，不能直接接受其他平台的 JSON 记录。相同内容已经通过完整 GitHub Test 时，要求本机重复相同验证仍会增加交付等待。CI runner 的临时历史也不能通过删除 Fresh 参数取得。

## 决策

保留本机记录和跨平台 CI 证明两种来源。Test 计划任务导出实际检出的内容树、提交、基线、范围、矩阵及运行身份。工作树 `ready --ci-run` 通过 GitHub 官方 API 核对运行来源、相同 HEAD、成功状态、有效期、证明制品摘要和全部所选任务。PR 的临时合并提交可以不同，但内容树须与最终工作树一致。

按差异验证的基线必须是当前内容的祖先，以待交付工作树重算的计划须与证明一致，覆盖当前交付范围；全量证明不依赖差异基线。跨根调用显式传递根目录，文件、权重和导入索引不读取调用方主检出的集合，索引缓存按根区分。缺少平台、分片、汇总、制品或摘要时均拒收。只重跑失败作业时，核对该运行每个任务的最新结果，原计划仍绑定相同运行和内容。

证明生成、选测和执行协议须与目标主线一致。修改协议的首个交付仍使用本机完整验证，不能用自己修改的证明协议为自己签发信任。协议集合在 `scripts/ci_test_evidence.py` 维护。

回执仅记录定位与核验摘要，集成时重新查询远端状态，不转换成本机环境证明。明确要求的本机桌面、特殊硬件、真实数据和生产验收仍单独取得。API 不可达时不能凭缓存的绿灯通过；有效本机记录仍适用。

## 验证

覆盖相同内容、不同提交和内容树、fork、协议改动、过期、缺失及跳过平台、失败和取消任务、作业重跑、制品摘要与回执再核验。以实际不同临时根验证主检出到工作树的计划、文件阈值与消费者选域，不仅在当前目录调用验证函数。首次协议交付执行本机完整回归与真实 PR CI，再核对真实证明可读取。
