# ADR-0139：核查差异按确定判据结算，复核页只留要人判的

- 状态：已采纳
- 日期：2026-11-04
- 关系：修订 [ADR-0108](0108-nfo-verification-and-reviewed-overwrites.md)「覆盖已有值必须复核」；ADR-0025 否决的归一化比对与来源优先级取舍只在本 ADR 划定的范围内放开；沿用 [ADR-0033](0033-online-sources-only-fill-empty-fields.md) 的社区来源只补空、[ADR-0038](0038-field-priority-chain-settles-dissent.md) 的字段优先级链与 [ADR-0052](0052-entity-results-land-when-evidence-is-sufficient.md) 的可撤回自动落库
- 补充：[ADR-0141](0141-review-page-reverts-settlement-writes.md) 让复核页逐条列出这两条规则的写入、勾选后预览并撤回，覆盖改为一次结算一个批次号

## 背景

2026-11-04 复核页待处理 2819 条，其中元数据字段 2775 条。逐条核对后，绝大多数挂在同一道门上：

- 有 NFO 的资产整条走核查模式（`library_processing._read_local_metadata` 返回 `nfo is not None`），升级补修的影片补全又以 `recheck_existing=True` 跑处理任务。两条路上，在线来源与账本现值不同的取值一律带 `requires_review`。10-28 与 11-04 两轮升级补修就带回 2533 条。
- 复核页把这些行从其余过滤器外面加回来（`overrides`），处理任务对它们一律跳过。快照里 2591 条是这一道挡住的，与来源可信度、取值是否真有分歧无关。

ADR-0108 记的是用户 10-17 的要求：「补漏无需复核，覆盖已有值必须复核」。11-04 用户在补女优资料的会话里说：「允许填，而且这个逻辑应该通用，让人工复核尽量少让人工去复核」。两次决定并列，本 ADR 的范围是：确定判据给得出结论的差异不再交人，结论要写账本时只写能整批撤回的，写不了撤回的照旧交人。

核查差异里大致有四类：

| 类别 | 例子 | 快照条数 |
| --- | --- | --- |
| 没有新信息 | 标签候选是现值子集；标题只差全半角、标点、打码字，或是现值的一段、去掉【】装饰后是；出演者按实体是同一批人 | 约 710 |
| 社区来源对非空现值的异议 | javdb 的配信日比发售日早几天；FC2 促销前缀；合集出演表 | 约 590 |
| 证据确定、能撤回的补充 | 标签候选里有账本没有的；官方来源一致给出的标题与日期 | 约 1070 |
| 真冲突 | 三家出演者全不同（ACC-006）；厂牌与 label 混写（HOISW-002）；系列命名不一；厂牌实体缺别名（`Deep's` 与 `ディープス`） | 约 80 |

## 决策

**一、核查差异只走一套判据。** `metadata_auto_apply.verification_outcome` 给一行核查差异定去向：保留现值、并集、覆盖或交人。复核页、处理任务结算与升级补修调同一个函数；复核页只把「交人」那一种摆出来，其余三种不占队列。`metadata_auto_apply_candidate` 不再接核查差异，避免链首覆盖（ADR-0035、0038）绕过这套判据。

**二、零写入的保留现值。** 下列情况账本不变，也不写决定：

1. 现值归人（`user:`、`review:`）；
2. 日期式番号的发行日期，现值就是番号那天（ADR-0034）；
3. 每条候选对现值都没有新东西（`_adds_nothing`）。标题按 NFKC、大小写、空白与标点折叠后比；候选一侧的打码字（`●`、`○`、`＊`，可盖住多个字）可对上任意字，现值打码、候选没打码的不算；候选是现值的一段，或去掉【】、［］装饰后是。出演者按实体身份是现值的子集，或整条剪不出艺名（企划名义与称呼）。厂牌、系列只差写法与码，或候选在现值后面加了读音与上级注记（`E-BODY（イーボディ）`、`Flower/妄想族`）。标签候选是现值子集；
4. 提出新东西的只有社区来源（ADR-0033）；
5. 链首那一档（本地 NFO、官方来源、字段上提到链首的来源）里有 NFO 以外的来源与现值一致；
6. 现值由链上更靠前的来源自动写入（ADR-0038 已经取过舍），例如 `auto:makers` 写下的 `HHH` 不被 dmm 的 `ロイヤル` 挑战。

兜底来源 javbus 不挑战已有值（ADR-0038 决策三），r18dev 给厂牌、系列的英文译名（`Amateur Pussies` 之于 `しろうとまんまん`）既不挑战也不作证，判断前先剔掉。

这里的归一化只用来判「保留现值」，结论不写账本。ADR-0025 否决的是拿归一化判两家「一致」然后落库；放在这一侧没有写入，被否决的那个风险不存在。

**三、可撤回的写入只有两种。**

- **标签并集。** 证据候选里认得出、账本没有的标签按链上先后补上，一个不删。复用 ADR-0082 的并集写法，标签行归属是批次号 `auto:metadata-tags@<时间>`。决定记 `rule: adr-0139-verified-tags-union`、`added_tags`、各次 `batches` 与当时全部候选身份。之后又收录了生词时，下一轮照样补。人批准过、已过期的标签决定按 ADR-0082 只增不删，原决定只追加 `added_tags` 与候选身份。
- **官方一致的标题与日期覆盖。** 链首那一档有异议的来源取值一致、现值不归人、没有更靠前的来源写过、番号身份核得上（`_auto_apply_targets`），按链首那一家覆盖，归属 `auto:<来源>`。决定记 `rule: adr-0139-official-replaces-verified`、批次号，以及每条资产覆盖前的取值与归属（`previous`）。

`scripts/revert_auto_landing.py --source <规则名> [--batch …]` 按决定撤回：并集删掉那一行补进的标签，覆盖把旧值与旧归属原样写回，之后被别人改过的资产不动。两种都删掉决定，下一轮按那时的判据重判，所以先改判据再撤。并集补的标签与 ADR-0082 同一个批次前缀，`--source auto:metadata-tags` 也能删掉它们，但决定里的规则名还在，下一轮会照样补回来。

按文件出的候选行（`asset:<编号>:<字段>`）此前按「编号＋路径」认文件。扫描按番号改指挪过的文件时编号不变（ADR-0131），处理任务重出同一行又沿用旧路径，2026-11-04 真实账本里 697 行因此谁批准都写不进去。落库闸（`_landing_scope`，人工批准与自动落库共用）改为：路径对不上、编号还在且番号相同，仍是这条资产；编号已不在库或成了别的番号，这一行保留现值、不入队。

**四、交人的只剩这些。** 本地 NFO 与链首来源说法不一（不论哪边是现值，核对 NFO 正是 ADR-0108 要做的事）；出演者有官方或链首来源异议；链首来源之间说法不一；厂牌、系列的官方异议；番号身份核不上；日期式番号的官方日期不是番号那天。

厂牌与系列在账本里是实体，换值连带改作品关联，撤回还不了原样；快照里这一类多是 maker 与 label 混写、系列命名不一、实体缺别名，确实要人判，不进覆盖。

**五、存量由升级补修结算一次。** `upgrade_rules.VERIFICATION_SETTLEMENT` 记规则版本。服务起来后，升级补修的后台调度对候选件里带核查标记的行跑一遍自动落库，先备份账本，结果记进 `ledger_upgrade_repair` 的 `verification-settlement-<版本>`；判据再变时版本加一。几千行要跑一两分钟，不放在启动前的 `prepare` 里：那一步挡着 `/healthz`，重启脚本默认只等 60 秒。不推进 `CATALOG`：那会重跑全部收集项，又以核查模式带回一批新差异。

## 理由

- 2591 条里需要人的判断只有几十条。其余要么什么都不用写，要么写的东西证据确定且能整批撤回，交给人只是让人重复代码已经得出的结论（ADR-0052）。
- 「覆盖已有值必须复核」防的是外部来源在无人知情时改掉判断。零写入的那几类不改任何东西；覆盖只发生在现值不归人、官方来源一致、链上没有更靠前的写入者时，旧值留在决定里，一条命令还原。
- NFO 是用户自己整理的资料，核查要回答的正是「它和发行方对不对得上」，所以 NFO 与链首来源的分歧仍然交人；社区来源对 NFO 的异议按 ADR-0033 不算。
- 判据放在领域层、复核页与处理任务共用，复核页上看不见的行，处理任务也不会悄悄跳过不落。

## 被否决的方案

- **只在复核页过滤。** 处理任务仍对这些行跳过，标签与日期一直不落；真实用户那边照样攒着这批待办。
- **厂牌、系列也按官方一致覆盖。** 写入要改作品与实体的关联，还可能新建实体；快照里的真实样例几乎都是 label 与 maker 的取舍或别名缺失，覆盖等于替人做身份判断。
- **有码作品的核查标签按 ADR-0100 整套换成 JavDB 的。** 换掉的旧标签不在可撤回的范围里；并集只增不删，旧的宽泛标签仍可由人在详情页删。
- **推进 `CATALOG` 让升级重跑处理任务。** 每部片会以核查模式再带回一批差异，正是这次要收的那种。

## 后果

- 对 2026-11-04 快照重放：2775 条里保留现值 1449、标签并集 967、官方覆盖 100、交人 75；另有 184 条不是核查差异（候选变了的过期决定、等收录的生词、补空落不下的描述性称呼），不归本 ADR。
- 在真实账本的拷贝上跑存量结算：标签并集 829 行、官方覆盖 100 行，撤回计划逐条认得回；复核页元数据队列从 2784 条降到 255 条，其中核查差异 75 条。并集判出而没写的 137 行，是同一条候选早先已落过、之后少掉的标签（多半是手删），不重补。
- 复核页的元数据队列每次多做一轮核查判断；资产按番号一次查齐，取数耗时与此前同一量级。
- 处理任务摘要多出 `kept`（核查差异保留现值的行数）。
- 核查行里来源还不认的生词不再单独摆上复核页；词在补空的行上照常等人收录，收录后下一轮并集照样补。
